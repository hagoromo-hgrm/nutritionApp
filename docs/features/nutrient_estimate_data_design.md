# 栄養素推計データ・校正設計

## 1. 目的

本書は、`docs/features/nutrient_estimate.md`を実装可能なデータ取得・教師データ・事前分布・精度校正の設計へ具体化する。正本は`docs/requirements.md`であり、矛盾する場合は正本を優先する。

採用する基本方針は次のとおり。

- 一般食品の正本は引き続き日本食品標準成分表（MEXT）とする。
- MEXTだけでは直接値がない工業原材料の補完にFoodData Central（FDC）を利用する。
- Open Food Facts（OFF）は、実行時の商品取得と、別工程で作るカテゴリ・原材料事前分布に利用する。
- 商品の表示値またはメーカー公表値を教師・評価の正解候補とし、OFFの栄養値を独立した正解データとは扱わない。
- 加工・調理による残存率や重量変化のモデル化は後続フェーズとする。
- 推定範囲は独立した校正データで校正し、信頼度を固定倍率だけで決めない。

## 2. ユーザー向け食品ジャンル

### 2.1 1項目での確認

原材料候補を1件ずつユーザーへ確認させず、食品登録画面で`estimatorGenreId`を1項目だけ確認または変更できるようにする。初期候補は次の順で決める。

1. ユーザーが以前に確定した値
2. OFFのカテゴリをローカル対応表で変換した値
3. 商品名ルールから推定した値
4. 原材料ルールから推定した値
5. `other_unknown`

候補が妥当な場合、「欠損値を推計」の実行をジャンル確認とみなし、ジャンルを確定するためだけの追加操作を要求しない。ユーザーがジャンルを変更した場合は、変更後の事前分布で再推計する。

ジャンルは候補の範囲を狭める事前情報であり、原材料表示と既知栄養値を上書きする根拠にはしない。複数候補の違いが推計結果へ大きく影響する場合も、原材料候補の専門的な選択を必須にせず、範囲を広げ、信頼度を下げ、理由を表示する。

### 2.2 初期ジャンル

| ID | 表示名 | 初期優先度 | 備考 |
|---|---|---:|---|
| `baked_sweets` | 焼き菓子 | A | クッキー、ビスケット等 |
| `cake_pastry` | ケーキ・ドーナツ | A | 洋生菓子を含む |
| `bread` | パン・菓子パン | A | 食パン、ロール、菓子パン等 |
| `chocolate` | チョコレート菓子 | A | カカオ・油脂候補の識別に有効 |
| `sugar_confectionery` | キャンディ・グミ・和菓子 | B | 多様性が高いため内部サブタイプを使う |
| `snack_rice_cracker` | スナック・米菓 | A | 油脂・穀類候補の識別に有効 |
| `frozen_dessert` | アイス・冷菓 | A | 乳・植物油脂候補の識別に有効 |
| `dairy` | 乳製品・乳飲料 | A | 乳原料候補の識別に有効 |
| `drink_jelly_pudding` | 飲料・ゼリー・プリン | B | 水分量が多い商品群 |
| `fried_food` | 揚げ物・フライ | C | 油吸収率を未実装の間は高信頼度にしない |
| `noodle_flour_dish` | 麺・粉もの | C | 調理前後の重量変化が大きい |
| `prepared_meal` | 惣菜・弁当・スープ | C | 原材料と工程の多様性が大きい |
| `sauce_spread` | ソース・調味料 | B | 高濃度・少量使用原材料を含む |
| `other_unknown` | その他・不明 | - | 広い事前分布を使用する |

ユーザーにはこの1階層だけを表示する。推計器は商品名、原材料、OFFカテゴリから内部サブタイプを推定してよいが、ユーザーへ専門的な分類操作を要求しない。

### 2.3 適用範囲

ジャンル選択によって、次を置き換えられる。

- 一般的な原材料候補の優先順位
- 原材料ごとの配合比事前分布
- 原材料位置ごとの使用頻度
- 共起する原材料による候補の絞り込み

一方、次はジャンル選択だけで置き換えない。

- `個`、`袋`、`ml`からgへの重量換算根拠
- 原材料表示にない原材料の追加
- 加工・調理による残存率や油吸収率
- パッケージまたはメーカーの公表値

## 3. 教師・評価データ

### 3.1 収集カテゴリ

最初の実装検証は、加工係数への依存が比較的小さく、既存の原材料辞書を活用できる次の3カテゴリを推奨する。

1. `baked_sweets`
2. `chocolate`
3. `bread`

教師データを一度に用意できる場合は、優先度Aの7カテゴリを並行して収集してよい。優先度Cは将来の加工モデル用にも保存するが、現段階の高信頼度評価へは使用しない。

### 3.2 必要件数

| 用途 | 推奨件数 |
|---|---:|
| 事前分布の本評価 | 1ジャンル100商品以上 |
| 小規模パイロット | 1ジャンル50商品以上 |
| 栄養素別の独立精度評価 | 1ジャンル・1栄養素30商品以上 |

30件未満のジャンル・栄養素は、近い上位グループまたは栄養素全体へプールして校正し、その旨を結果メタデータへ残す。

同じ商品の容量違い、味違い、リニューアル前後が学習と評価へまたがらないよう、メーカーと商品系列のグループ単位で分割する。目安として、1メーカーまたは1商品系列が各ジャンルの20%を超えないようにする。

### 3.3 必須フィールド

UTF-8のCSVまたはJSONで、少なくとも次を受け取る。

- `recordId`
- `genreId`
- `productName`
- `maker`
- `productFamily`（容量違い、味違い、更新前後を同じ分割へ固定する系列ID）
- `barcode`（任意、文字列）
- `ingredientsText`
- `ingredientsLanguage`
- `baseAmount`
- `baseUnit`
- `referenceMassG`
- `referenceMassSource`
- 各栄養素の表示文字列、数値、単位、表示基準、小数桁数、`valueKind`
- `sourceType`
- `sourceReference`
- `verifiedAt`
- `notes`（任意）

`valueKind`は`fixed`、`declared_range`、`estimated`のいずれかとする。欠損はゼロへ変換しない。`estimated`表示は学習用の補助には使用できるが、独立評価の正解からは原則除外する。

写真を提供する場合は表データと分離し、`recordId`で参照する。出典、利用許諾、再利用可能範囲を記録したマニフェストを添える。購入者、購入場所、摂取履歴等の個人情報は収集しない。

### 3.4 分割

データは商品系列グループ単位で次のように固定分割する。

- 学習: 70%
- 校正: 15%
- 最終テスト: 15%

最終テストは事前分布、候補辞書、係数および信頼度閾値の調整に使用しない。分割表、元データハッシュ、変換版を保存し、同じモデル版を再評価できるようにする。

## 4. FoodData Central

### 4.1 利用境界

FDCはPythonによるビルド時の取得・検証に使用する。PWAからFDC APIを直接呼び出さない。APIキーは環境変数`FDC_API_KEY`からだけ読み、クライアントコード、生成物、ログおよびGitへ含めない。

取得した生データはGitやPWAへ同梱せず、レビュー済みのFDC ID許可リストから、アプリ用の工業原材料プロファイルを再生成する。欠損値は`null`のまま維持する。

### 4.2 採用優先順位

1. MEXTの直接項目
2. FDC Foundationの直接項目
3. FDC SR Legacyの直接項目
4. メーカー等の検証済み仕様値
5. 栄養特性が近い食品による代理参照

FDC Branded Foodsは個別商品の情報であり、一般的な原材料プロファイルとしては採用しない。直接値を採用できた場合は、ココアバター等のMEXT代理参照を置き換える。

### 4.3 生成物メタデータ

各プロファイルに次を保存する。

- FDC ID、description、data type
- FDCデータ版またはリリース
- 取得日時と取得元URL
- CC0であることと帰属文
- 100g基準であること
- 生データのSHA-256
- 正規化処理の版
- レビュー状態とレビュー日

設定画面またはデータ出典画面に、MEXTと区別してFDCへの帰属を表示する。

### 4.4 初期導入状況

2026-07-26時点の公式Foundation Foods 04/2026およびSR Legacy 04/2018を確認し、SR Legacyの`fdcId=171421`（`Oil, cocoa butter`）をレビュー済みココアバター直接プロファイルとして採用した。これにより、ショートニングによるココアバター代理参照を置き換える。

乳糖とカカオマスは純原材料として採用できるFoundation/SR Legacy直接項目を確認できていないため、レビュー待ちとし、既存のMEXT代理参照、低信頼度および警告を維持する。FDC Branded Foodsで名前が一致する商品は、一般原材料プロファイルとして採用しない。

## 5. Open Food Facts

### 5.1 実行時取得

実行時は現行どおりJAN/GTINだけを送信し、栄養値、商品名、原材料、カテゴリ候補を取得する。取得値は編集可能な候補として表示し、ユーザー確認後に保存する。OFFの停止、欠損またはオフライン時は手入力へ切り替える。

### 5.2 事前分布の作成

バルクデータまたは検索APIから、次の文字・分類情報だけを抽出する。

- `code`
- 商品名と主要言語
- `categories_tags`
- `countries_tags`
- 原材料表示、言語、正規化タグ、未知原材料数
- 内容量
- データ品質・完全性・状態
- 最終更新日時

栄養値は異常検知や層化には利用できるが、教師データの独立した正解にはしない。画像は初期版では取得・再配布しない。

OFF由来データから、概ね次の条件付き分布を生成する。

```text
P(原材料候補 | 正規化原材料名, ジャンル, 表示位置帯, 共起原材料, 商品名トークン)
```

低頻度条件には平滑化を行い、商品数が閾値未満ならジャンル全体または全商品へ縮約する。商品名は弱い事前情報とし、原材料の明示語や既知栄養値との整合を上書きしない。

ローカル生成器は、既定で日本向け商品、完全性0.5以上、原材料あり、未知原材料3件以下へ絞り、レビュー済みOFF原材料タグだけをアプリ内プロファイルへ対応付ける。商品コードと個別商品名は出力せず、商品名トークンは5商品以上に現れた集計だけを残す。

### 5.3 ライセンス分離

OFF由来の事前分布は、MEXT/FDCの参照プロファイルとは別生成物にする。生成物へ元データ版、取得日、ODbL、Database Contents License、変換版を記録する。

アプリへ同梱・配布する前に、ODbLの帰属、Share-Alikeおよび対応するデータベースの提供方法を確認する。初期段階はローカル検証用生成物として扱い、条件を満たした後に配布用バンドルへ切り替える。

## 6. 表示値を正解として扱う範囲

固定表示値を誤差ゼロの点とは扱わず、丸め幅と表示制度上の許容差から正解区間を作る。損失は区間内をゼロ、区間外を区間端からの距離で計算する。

区間の優先順位は次のとおり。

1. パッケージに表示された範囲
2. 固定値に丸め幅と栄養素別許容差を適用した範囲
3. 「推定値」表示に、実測校正から得た広い範囲を適用した範囲

表示上の`0`は真のゼロとみなさない。栄養素ごとの許容差、低含有量時の絶対許容差、適用日および根拠資料は、コードへ散在させず版付きルールデータとして保持する。

## 7. 推定範囲と信頼度の校正

推定範囲は、学習および最終テストから分離した校正データで、split conformal等の被覆率を直接評価できる方法により校正する。暫定目標の被覆率は90%とする。

校正単位は次の順で選ぶ。

1. 十分な件数があるジャンル・栄養素
2. 近い上位ジャンル・栄養素
3. 栄養素全体
4. 固定倍率による暫定範囲

結果には`calibrationVersion`、目標被覆率、実測被覆率、標本数、校正データハッシュを保存する。高信頼度は、独立標本数、被覆率、相対的な範囲幅、候補の一意性をすべて満たした場合に限る。加工係数を後回しにするカテゴリ・栄養素は、高信頼度にしない。

教師・校正データ受領前は、`scope=fallback`、`sampleSize=0`を明示した版付き暫定範囲を使う。これは90%被覆率を達成した校正済み範囲とは表示せず、結果と採用後メタデータへ校正状態を保存する。参照プロファイルの全候補が根拠付きで0の場合だけ範囲`0..0`を維持し、パッケージの表示上の0とは区別する。

## 8. 未解決原材料の端末内収集

推計できなかった原材料を、ユーザー操作なしに外部送信しない。IndexedDBには次の集計だけを保存できる。

- 正規化原材料名
- 個人情報を除いた短い表示例
- ジャンル
- 出現回数
- 初回・最終出現日時

バーコード、商品名、メーカー、食品、食事記録への参照は含めない。設定画面からJSONまたはCSVを手動出力できるようにし、完全バックアップとは別形式にする。

## 9. 実装順

1. ジャンル型、対応表、教師データスキーマ、分割検証器
2. 食品登録画面のジャンル候補・確認とIndexedDB/JSONバックアップ対応
3. FDC取得・許可リスト・正規化・再生成パイプライン
4. FDC直接項目による工業原材料代理参照の置換
5. 栄養表示の正解区間ルール
6. 未解決原材料の端末内集計・手動出力
7. OFFのローカル事前分布生成パイプライン
8. ジャンル・位置・共起・商品名事前分布の推計器統合
9. 独立校正データによる推定範囲と信頼度の校正
10. 最終テスト評価とモデル版更新
11. 加工・調理係数

## 10. 確定した意思決定

ユーザー確認により、次を採用する。

1. 推定範囲の目標被覆率は90%とする。
2. 教師データは焼き菓子、チョコレート菓子、パン・菓子パンの3ジャンルでパイロットし、その後に優先度Aの7ジャンルへ拡張する。
3. OFF由来事前分布はローカル検証に限定し、ODbLの配布条件を満たした後に同梱を判断する。

教師データなしで実行できるジャンルUI、初期事前分布、教師データ検証・固定分割、FDCレビュー済み生成、表示値区間、暫定校正メタデータ、未解決原材料集計、OFFローカル生成器は先行実装する。独立校正と最終テストによる閾値確定だけを教師データ受領後に行う。
