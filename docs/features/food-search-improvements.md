# 食品検索の改善案

## 文書の位置づけ

- 作成日: 2026-09-13
- 調査対象: `0b0860e` 時点の実装
- 状態: 採用。第1・第2段階を実装対象とする
- 目的: 食品を見つけやすくし、検索から食事登録までの操作を減らす

本書は会話で検討した頻度による順位改善と、それ以外の改善案をまとめたもの。要件の正本は [requirements.md](../requirements.md) とし、本書だけで仕様を変更しない。[既存の食品検索機能要件書](food-search.md)には過去の背景説明も含まれるため、以下の現状整理は実際のコードを基準とする。

## 1. 現状と課題

| 対象 | 現状 | 課題 |
|---|---|---|
| 通常食品の順位 | 名前・別名・メーカー・読み等の一致点に、代表性、選択回数、お気に入り、直近の選択による点を加算 | 頻度点は約11回の選択で上限に達する。累積回数は時間で減衰しない |
| MEXT由来の一般食品 | 別の検索処理で並べた候補を通常食品の前へ配置 | 通常検索の個人向け加点が反映されない |
| 利用実績 | 検索結果からの選択時に加算 | キャンセルやFOODMASTERでの閲覧も含む一方、属性選択から直接食事を保存する導線では計上されない |
| 追加表示 | 食事登録側ではMEXT候補を先頭20件に制限し、通常食品側だけ追加取得 | 表示していないMEXT候補の構成食品も通常食品側から除外するため、候補へ到達できない場合がある |
| 検索文字列 | 通常検索とMEXT検索で正規化規則が異なる | 表記によって検索経路ごとの結果に差が出る。通常検索は空白を除去し、複数条件としては扱わない |
| プレビュー | 通常検索では一致した食品とは別の既定食品を代表表示する場合がある | 検索条件と表示名・栄養値が一致しない場合がある |
| 評価ログ | 通常食品の検索ページを記録した後、画面側でMEXT候補やメニュー等を統合 | ログの候補・順位と画面の候補・順位が一致しない |
| 検索時の読み込み | 食品・グループ・別名・関連語・利用統計等を全件配列として取得 | データ増加時の時間・メモリ使用量は別途計測が必要 |

## 2. 頻度を使った順位改善

### 2.1 実際の食事保存を利用実績とする

検索結果を開いた回数と、実際に食事へ登録した実績を分ける。順位の主要な根拠は保存成功とする。

- 検索・履歴・お気に入り・属性選択等の登録導線で、実績の定義を揃える。
- 閲覧、キャンセル、保存失敗では加算しない。
- 既存記録の分量修正、再保存、並び替えでは加算しない。
- コピー、JSON復元、CSV取り込みで実績を二重計上しない。
- 保存済みの食事記録から再集計できる統計を基本とする。

削除・食品変更時は保存中の食事記録から再集計する。直接選択していないMyメニュー、一般メニュー、一時メニュー、Myセットの構成食材は初期実装の利用実績に含めない。過去の検索選択回数を、そのまま食事保存回数へ読み替えない。

### 2.2 関連性を保った順位付け

次の順序を基本案とする。

1. 名前や別名の完全一致、前方一致、部分一致、関連語等で検索語との関連性を分ける。
2. 同程度の関連性の中で、最近よく使う食品を優先する。
3. 登録対象の食事区分での利用と、お気に入りを補助的に加点する。
4. 同点の場合は固定の順序で並べる。

通常食品とMEXT食品は現在の点数の尺度が異なるため、生の点数を足し合わせず、共通の一致度区分へ対応付ける。既存の肉の部位や卵の種類へのショートカットは維持する。

例として「牛乳」ではよく登録する牛乳を優先する。一方、「低脂肪牛乳」では、普段の普通牛乳より入力条件に合う候補を優先する。頻度だけで検索条件に合わない食品を上位へ持ち上げない。

### 2.3 頻度以外の個人向け指標

| 指標 | 使い方 |
|---|---|
| 利用日数 | 同じ日に何度も保存した食品だけが突出しないよう、回数と併せて使う |
| 利用の新しさ | 古い実績の影響を徐々に弱め、現在の食習慣へ追従する |
| 食事区分 | 朝食登録中は朝食でよく使う食品へ補助的に加点する |
| お気に入り | 明示された好みとして加点する。お気に入りタブの手動順序は変更しない |
| 検索語との組み合わせ | 同じ検索語から繰り返し保存する食品を優先する。初期改修後の追加候補とする |

初期値は、対象期間180日、指数減衰の半減期45日、最近利用の表示期間30日とする。個人向け加点は頻度8点、異なる利用日数7点、新しさ4点、同じ食事区分4点、お気に入り2点の合計25点を上限とする。ただし、この点数は文字列の関連性が同じ区分にある候補間だけで比較し、完全一致、前方一致、部分一致、関連語の順序を越えない。値は暫定とし、実際の検索例で比較して調整する。食品グループへの利用傾向と、部位・調理状態等の種類への傾向は分けて扱う。

## 3. 頻度以外の改善案

| 改修 | 例・期待する効果 | 実装時の注意 |
|---|---|---|
| 候補の取りこぼし解消 | MEXT候補も「さらに表示」で最後まで到達できる | 候補統合・重複除去・順位付けの後に表示ページを区切る。内部の取得方式は性能を測って選ぶ |
| 複数語による絞り込み | 「明治 ヨーグルト」「鶏肉 皮なし」の各語をメーカー・名前・属性へ照合する | 単語境界を残して解釈する。既存の単一語検索とバーコード完全一致を維持する |
| 検索条件を属性選択へ引き継ぐ | 「鶏むね 皮なし」で対応する種類・属性を選択済みで開く | 明確に対応できる条件だけを反映する。曖昧な条件を推測で確定せず、保存前に選択内容を確認できるようにする |
| 別名・略称の充実 | 普段の呼び方で食品を見つけられるようにする | 既存の別名機構を活用し、見つからなかった検索語から不足を補う。意味の異なる食品は同義語にしない |
| 表記揺れの扱いを揃える | 全半角・かな・記号等による検索経路間の差を減らす | 正規化を変える場合はMEXTの生成済み索引も同じ規則で再生成・検証する |
| プレビューの整合 | 検索語に一致した種類の名前・栄養値を代表表示する | 曖昧な一般名では従来の代表表示を使うなど、明確な条件がある場合と区別する |
| 過去の検索語候補 | 一度使った検索語を短い操作で再入力する | 保存につながった検索を優先する案。端末内で保持し、削除可能にする |

誤字の自動補正や意味の近い食品を探す検索は後回しとする。部位・調理状態・商品違いを混同しないよう、まず入力条件を正確に扱う改修を優先する。新しい検索エンジンや機械学習基盤の導入は初期改修に含めない。

## 4. 操作とデータ保全の方針

- 連続追加中は検索結果の順位を固定し、保存による統計更新は次の検索から反映する。
- 検索語や分類を変えた場合は、新しい検索として追加読込状態をリセットする。
- 食品の都度保存、未選択結果の保持、「確認」を押すまで連続追加する動作を維持する。
- 食品登録・編集は保存後も画面に留まる動作を維持する。
- 食品とメニューの既存分類・表示方針を守る。メニュー検索の順位変更まで初期範囲を広げない。
- 個人向け統計はIndexedDBで保持し、オフラインで利用できるようにする。
- 統計の保存形式を変える場合は、スキーマ移行とJSONバックアップ・復元を確認する。

## 5. 改修の優先順位

### 第1段階: 順位改善の土台

1. MEXT候補の取りこぼしと追加表示を修正する。
2. 利用実績を保存成功基準に揃える。
3. MEXT食品・通常食品に共通の一致度区分を設け、頻度・鮮度・食事区分を反映する。
4. 検索ログを実際の表示候補・順位に合わせる。

### 第2段階: 入力と選択の手間を減らす

1. 複数語検索を追加する。
2. 明示された種類・属性を選択画面へ引き継ぐ。
3. 一致した種類とプレビューを揃える。
4. 別名や表記揺れ、一致箇所の表示を改善する。

### 第3段階: 効果を見て追加する

- 検索語ごとの保存実績による加点。
- 過去の検索語候補。
- 計測で必要性が確認された検索時間・メモリ使用量の改善。

性能改善は順位改善と分けて検証する。revert済みの `3721d82` の再適用を前提とせず、端末での応答時間と候補の網羅性を測って方式を選ぶ。

## 6. 検証方法

### 使いやすさ

- 目的の食品が上位5件に入る割合。
- 「さらに表示」を押す回数。
- 検索から保存までの操作数・所要時間。
- 検索しても保存に至らなかった例の確認。未保存を直ちに検索失敗とは扱わない。
- iPhoneでの初回検索・再検索・追加表示の応答時間。

ログは候補統合後の画面に合わせ、候補ID、表示順位、検索の文脈、保存成功を対応付ける。追加ページでも順位の基準を揃える。大きな分析基盤は導入しない。

### 回帰確認

- 検索条件が明確な食品を、頻度だけで不一致の食品が追い越さない。
- MEXT候補が20件を超えても全候補へ到達でき、重複や欠落がない。
- 閲覧・キャンセル・失敗・編集で頻度が増えず、各登録導線からの保存が反映される。
- 同じ検索中は保存や追加表示で既存候補の位置が動かない。
- 複数語、別名、かな・全半角、分類、バーコード完全一致を確認する。
- 部位・調理状態・単位を推測で変更しない。
- オフライン検索、旧データからの移行、バックアップ復元を確認する。

点数や期間は2.3の初期値から開始し、これらの確認例と測定結果を用意したうえで調整する。
